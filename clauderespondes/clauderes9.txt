Result

I fixed Bug 1 and Bug 2 and left Bug 3 alone as agreed. Bug 1 turned out to be two faults, not one: Cognito's discovery document advertises an end_session_endpoint, which makes oidc-client-ts attempt a standard RP-initiated logout that Cognito does not implement, and the app client had no allowed sign-out URLs at all. I registered the sign-out URL first, then probed the live endpoint to find out which query shape Cognito actually honours before writing any code — which was worth doing, because it proved that post_logout_redirect_uri does not work and the otherwise-obvious fix would have failed. Bug 2 was not a timing window but a duplicate dispatch: App.jsx and Layout.jsx both called the store's login(), and only Layout passed a token, so one of the two requests could never succeed and could overwrite a loaded history with an empty one. The build succeeds, lint is unchanged against its baseline, and all three fixes are present in the built bundle. Nothing is deployed — no commits, no pushes.

Findings

- [P0] Cognito had no allowed sign-out URLs (LogoutURLs: null). Logout could not have worked for any user regardless of client code. Fixed in configuration; live now, no build needed.
- [P1] Cognito ignores post_logout_redirect_uri. Configuring it and keeping signoutRedirect() looks like the natural fix and  + logout_uri does. Recorded in FINDINGS so nobody re-derives it.
- [P1] Two history requests were issued per login, one permanently unauthenticated, and both wrote to the store unconditionally, so the outcome depended on which finished last. Confirmed in the deployed bundle, not just in source.
- [P1] Every history failure was silent. The 401 branch produced history: [] with no error flag, making a failed load indistio assessments.
